# 移动载具乘客与旧位置修复的冲突

信号：世界坐标保存正确，但乘车读档后乘客被移到车外；手持物随角色丢失/复制；暂停 UI 时车辆仍动。

机制：乘客的位置由载具与座位共同决定。旧角色恢复只认识地面和座椅，道路车辆的碰撞盒会被当作错误出生点；随后逐帧修复会破坏乘坐关系。只保存玩家坐标也不能重建车辆和相对位置。

本项目处理：`CityTransit` 保存带版本线路、距离、停站、乘坐/下车请求与探索状态；v12 整体校验后恢复。先清除旧绑定，再恢复玩家，再从车辆座位生成乘客位置和碰撞/镜头例外。已绑定乘客跳过通用地面位置修复；下车只有停站且物理落脚检测通过时生效。乘车先将唯一手持物收纳，禁止车内取出/投掷。车辆使用可暂停节点的物理时钟。

支持案例：`tests/city_transit_test.gd` 真实 JSON 写读和等待旧位置修复回调、非法交通字段不修改世界、v11 导入、路障/出口阻挡、物品唯一性；`tests/city_controls_test.gd` 真实 E/M/鼠标/Enter 的上下车与地图。`tools/verify_macos.gd` 两目录实际启动器也验证乘车恢复。

验证状态：2026-09-29 C1与C2a均经定向、全套及独立包验证。C2a（01b4ea4）扩展到两辆可用车/三辆通行车：v13整体校验唯一驾驶与公交互斥，先detach旧绑定、恢复载具、双向碰撞例外和镜头例外，再按座位恢复人；暂停/失焦/读档清除本地按键状态，只有新的按下事件才能恢复油门。`tests/city_driving_test.gd`检查真实JSON往返、旧位置修复回调、v1—v12夹具、非法字段不改变驾驶状态、下车双侧阻挡；包内探针用真实W事件验证驾驶与恢复。

边界：当前仅平地街区、固定已知五车、单一驾驶者和一条公交线路。未证明多人上下客、车辆生成/回收、分区卸载、地形改变后的载具重定位或超过 ±1000m 的位置迁移；不能把本结论泛化为完整交通存档已经完成。旧版本夹具不是历史玩家档全集。

2026-09-30 C2c将上述所有权规则用于既有公共居民。v23把候车节点、原目的地、公共座位和公交变换关联校验；恢复先拆旧绑定，恢复公交/人物，再重建公共乘客绑定，地面迁移跳过车上居民。候车只是交通中间环节，不能额外递增居民的生活活动序号；原地点到达才完成一次活动。专项覆盖五公共座位、保留玩家座位、四站、危险/救助交接、暂停、17类坏档和旧v1—v22构造JSON。

同帧下车的新反例：三个实际居民在同一物理帧落到站台中心，最小间距0.003221m；逐人调用物理查询仍通过，因为前一个节点的位移尚未更新到物理空间。`CityPassengers.clear_exit`同时检查当前人物节点位置；显式跳过等车另预先预约整批落脚点。`city_passengers_save_test`必须在多次attend之间不await物理帧，否则会掩盖原触发。自然同乘图形复验最小间距1.100423m，见`docs/evidence/2026-09-30-c2c-passengers/initial-findings.json`和同阶段路线。该同帧机制验证一次，不外推任意交通工具/坡地/跨区。

边界夹具注意：Godot的PROCESS_MODE_DISABLED会将相关物理对象移出空间，不能用于验证冻结障碍物。此处仅关闭脚本的process/physics_process并保留碰撞体；中途车流占站必须让跳过等待失败，测试让车辆实际驶离后再验成功，不能移除路障判定来得到绿灯。上下客仍为受限站台/座位交接，正式踏步和车内走动未完成。

2026-10-09 F05：接管公交后原route distance仍只能表示原运营位置，不能用它校验偏离路线后的乘客位置。v27/驾驶schema2明确taken与实际公交变换，乘客验证和恢复使用同一变换，并交叉拒绝公交/驾驶双份坐标不一致；驾驶与乘坐仍互斥。司机离车是独立现场人物，原坐姿司机隐藏、路线上自动行驶停止。实际停车退出使用附近落脚和侧面视线，不能把乘客传回旧站台。`feedback_vehicle_test`六车物理移动、实际JSON文件往返、车内接管与带乘客偏线、停车退出及坏关联原子拒绝通过一次；正常city_transit/city_passengers/city_driving仍通过。当前仅现有车辆，司机交接与上下客是简化动作，不外推生成车辆、坡地或分区卸载。

F05实际UI补充：从公交页面接管时，仅清conversation不会关闭暂停页面；直接调用enter并手动drive的夹具无法发现这一点。改用真实E目标与公交按钮回调，并断言页面关闭/SceneTree不再paused；CityDriving.enter通过统一show_page("")完成所有权交接。另一个夹具反例是F01先设12m/s再enter，新低速接管规则正确拒绝它，后续存档错误只是“移动无人车”的非法夹具；应先停稳建立实际驾驶关联，再给定碰撞速度，保留完整校验。


## 2026-10-10 MOT01—02：路线控制不能覆盖受撞后的实际运动

确认机制：`CityCar.drive`原先碰撞只清零速度；车流/公交每帧由路线生成变换。只加镜头震动，或只给被撞车写一次位置，均不能建立持续物理运动；恢复时仍按路线检查还会拒绝偏离路线的事故档。

处理：引擎速度与残余平面速度/角速度分开，接触点冲量按质量/转动惯量分配；位移和角度均扫掠，阻尼使其停稳。事故后自动驾驶暂停，保留真实位置。驾驶schema3保存碰撞状态，读取schema1/2仍保留旧路径约束；公交独立碰撞位置通过`stored_transform`同步乘客与校验。下车/接管既看引擎速度也看滑行速度。抢车所有权先确定，人物视觉连续离座/入座，期间禁止油门和重复下车；保存途中恢复已完成交接的安全状态。

验证一次：`tests/vehicle_motion_test.gd`：30/60/120Hz偏撞位移4.860565/4.844254/4.832748m；连锁第三车2.303596m；同次撞击小车4.718620m/公交0.327301m；JSON、拒绝非法冲量、连续动作与重复E均通过。图形复核见`tools/render_motion_feedback.gd`，状态结果不等于正式动画自然度验收。

边界：当前平地平面冲量，不是悬挂、翻滚、轮胎抓地或软体损坏。事故车辆不会自动回到路线，公交停运后可就地下车/接管；尚无自动清障与恢复运营。入座为现有人体动画/根变换混合，不是完整双人动作捕捉。


MOT01补查：玩家`drive`、车流`tick_traffic`、公交`tick`是三个独立碰撞入口，不能只修一个。自动入口复用冲量后，公交需要提前制动保持正常跟车。已有`city_transit_test`进一步发现新预判制动虽然已停稳，却未设置blocked，使“道路实体障碍让公交停车”断言失败且会影响跳过等车资格；修正为预判有障碍并停稳时标记blocked，保留原断言重跑通过。`vehicle_motion_test`新增两种自动入口突然被阻挡用例，`city_traffic_test`自然三车整环零重叠复验通过。
