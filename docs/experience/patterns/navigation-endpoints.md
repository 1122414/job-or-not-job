# 工位终点与寻路阈值

信号：员工离开座位后返岗停在座位外约一米，反复朝隔板移动。
机制：1m 网格和 0.85m 查询宽度把窄桌前座位映射到别处；路线只到格点，没连接真实座位。改为 0.5m 网格后，若停止距离 0.35m 大于航点移除距离 0.28m，会在航点前永远停住。
处理：0.5m 网格，匹配角色宽度；末段 capsule sweep 确认无阻挡后连接实际终点。移动停止阈值小于航点消费阈值；无路不朝障碍直冲。
验证：`tests/npc_lifecycle_test.gd` 从分离的过道位置让全部 10 位 NPC 真正返岗，修复前 8 位失败，修复后通过。首次测试把多人放在同一点导致弹上屋顶，那是无效夹具，已改用分离起点。
边界：不保证所有动态家具堆叠可穿越；物品改变后需重建路网，真实堵死的路允许无法到达。

2026-09-22：当工位椅开始参与人物碰撞时，导航仍只检查layer1会反复选择穿椅路径。网格与末段检测改为mask3，只在目标为自己的座位时排除该座椅。十人返岗与实际来访测试通过一次；复杂全封闭通道仍需清障，不能以瞬移解决。

2026-09-22 面试串联反例：到达目的地的测试通过不证明经过设计入口。第三轮门口拥堵暴露后排桌板挡门，前两轮走侧缝。先检查每段真实位置，再修布局；临时人物避让不要把0.5m网格的整块3×3都封死，应按实际中心距离标记。封闭侧缝、移动后排、3m门洞后连续四轮及接替者入场通过一次。证据：tests/interview_test.gd、tests/scene_driver.gd、scripts/office_rooms.gd。仍不保证完全堵死通道可通行。

2026-09-22救助人员：每帧从当前位置重算格点路径，会在相邻格点间反复返回起点。缓存路径并消费航点、0.8秒重规划后nonlethal_care_test通过。不要把更频繁重规划等同更可靠的移动。渲染截图等待frame_post_draw时场景可能继续推进，分阶段取证需冻结世界，避免把下一状态标成当前帧。

2026-09-29资产接入反例：新候场椅深度大于原方块长凳，带领终点落入膨胀占用格；完整职业路线实际停在终点外。后移椅子0.5m恢复连续路线，未改导航容差或碰撞掩码。`environment_assets_test.gd`补A/B终点末段通行检查；详见`open-asset-integration.md`。既有导航实现正确也不能免除新布局回归。

2026-09-29 公共城区：办公室网格仅覆盖约70×43m，首区公共居民改用独立连通步道图、缓存路径和真实胶囊移动，不能直接套用办公室格点。`city_population_test`观察12人各抵达至少两个活动点，三处过街与车流同时运行。过街中途倒地后起身必须继续走完当前跨路段，再选择新目标；不能立即清除通行身份，让车辆提前恢复。`city_crossings_test`真实JSON恢复、倒地/起身、走完跨路段与车辆恢复通过一次。边界：固定首区路网，尚未证明整城导航、动态封路重规划或死亡后的公共救助；完全堵路需要清障。

公交补充检查：8m/s公交制动2.4m/s²，18m车头中心距离不足以在预留6.1m的停止位置前停稳。固定13m接近阈值曾使居民提前获准过街（`city_crossings_test`观察失败）；改按制动距离判断。不能用瞬停满足不可能的测试：18m场景验证居民等整车清空，24m场景保留公交确实停在线前并恢复的独立断言。最终结果见本阶段验收，不把第一次不合理停线期望当成引擎物理失败。

2026-09-29 C3b复用：死亡现场释放路权之前，先由常驻小组沿公共图抵达并实际转运。路权占用从居民跨路身份交给小组的真实路面范围；小组离路才解除，不能仅清空dead居民的crossing。`city_response_routes_test`三处路口观察真实车流停线与恢复，书屋室内转运也完成；原`city_crossings_test`非致命倒地/恢复与公交制动继续回归。接收站保留身体、死亡和碰撞，未实现完整医院后续。

该次导航反例：伤者贴地后的根坐标约有毫米级负Y，直接把这个差值加入救助末段方向，会让test_move检查斜向地下的位移，小组停在路口前。用同位置纯水平探针没有碰撞；目标与运动方向投影到首区地平面后四条实际路线通过。适用边界是当前平坦首区，不可直接推广为坡地或楼梯忽略高度；相关代码`scripts/city_response.gd`、测试`tests/city_response_test.gd`。验证一次。

2026-09-30 C3e：办公室细网格通过z=18入口连接公共步道。若办公室判定边界延伸到z=22，0.8秒重规划会把刚出门的人反复送回入口；应统一实际交界，而非加快重算。六段真实同行覆盖出门、到场及返程。

同阶段花园返程遇到站立玩家：原OfficeNPC避让只包含其他NPC/居民，546次玩家接触确认堵塞。加入玩家后仍围绕路径投影绕圈；近处投影只是入路辅助，后续节点可静态扫掠直达时允许跳过。定向场景最终净前进19.5371m、最大单步低于0.038336m，玩家XZ不变。不能为了通行关闭人物碰撞。独立站位夹具需等已有异步恢复结束，首帧位置修复不能计为正常移动。

更隐蔽的反例出现在独立包：中心步道实际跟随在z约26—29来回走，输入/健康/站姿正常，唯一接触是法线竖直的地面。单点路径检查正常；沿路100点扫描发现6点回头至z=18。原因是公共图同时保留整段south→center和细分south→commons_south，最近点浮点误差使起终点落在不同但重叠的图边，端点最短路把人物先带回旧路口。`CityFootRoutes.on_link`检查投影点位于同一段，静态扫掠确认后直连；不删除旧存档依赖的图边。双向200点和原失败的独立包完整实际同行已验证一次。最终全套结果见`docs/2026-09-30_C3e同事进入公共生活验收.md`。

边界：这些处理只覆盖固定首区步道、近处避让及平地入口，不代表动态封路、复杂人群、坡地/楼梯或整城分区已解决。诊断顺序应同时记录真实运动、输入、路径和碰撞；地面出现在碰撞列表中本身不能证明是地面阻路。
