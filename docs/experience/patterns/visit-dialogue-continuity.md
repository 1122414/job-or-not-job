# 来访确认后的交谈对象连续性

适用信号：NPC 抵达后可以确认来访，但下一次 E 打开工位或拿起道具，职业选项看似消失。2026-09-22 带渲染完整路线在 a_boss / defend 失败，纯 headless 路线通过，说明单次快速状态检查不能覆盖移动和到访时序。

机制：确认来访清除 arrived 优先级并关闭 conversation；重新调用 nearest 时，工位的距离权重可能超过刚确认的 NPC。此前只对 B 公司欢迎保留 speaker，其他来访仍断开。

处理：确认成功后从原 visitor 重新获取当前职业选项并继续交谈；稍后再聊仍关闭。新的选项必须在 answer_visit 更新职业状态之后计算，避免重复发放 brief / no_hc 成果。保留已有距离、死亡和倒地中断判断。

验证：tests/office_life_test.gd 覆盖老板来访确认后 speaker 保留且立即含 defend 选项，0 失败；tests/full_route_test.gd 增加空对话诊断。完整渲染路线结果见当日整改验收记录。此结论在本项目验证，不代表所有对话都应保持窗口（拒绝、离开仍应关闭）。

测试边界：带画面脚本仍会接收真实桌面键鼠。2026-09-22 CUA 实际观察到完整路线窗口停在暂停菜单，脚本却仍等待行走，不能把这类失败记作 WASD 或寻路缺陷。自动路线和性能夹具使用 Viewport.set_disable_input(true) 并释放鼠标，只保留脚本显式驱动的 Input.action_press；手动 GUI 验收不采用此设置。
