# 开放资产的许可、语义与空间通行分别验证

信号：资源可导入且摘要正确，但新家具朝墙、夹桌结构悬在桌上、贴图与场所不符，或旧职业路线突然停住。

机制：CC0证明使用授权，不证明风格、坐标朝向、安装方式与项目一致。几何AABB底部并不总是支撑点；夹桌灯原点接桌沿、夹具应在桌面下方。家具真实尺寸还会改变导航网格的终点占用。

处理：原件、许可和校验清单保留；tscn包装碰撞/安装点，tres定义材质尺度，不破坏原始文件。导入后查看正常游玩及独立特写，再验证动态路线。来源文件类别只能用于筛选；本轮concrete_floor_02实拍斑驳过强而拒收，01仅用室外，办公室保留原地毯。不要用“贴图更复杂”代替场所可信。

案例：2026-09-29 P1接入。新椅占地使入职带领的(-10,0,0.2)终点不可达，`full_route_test.gd`失败2项；椅子后移0.5m恢复，原测试阈值保留。`environment_assets_test.gd`追加A/B终点胶囊通行与正确朝向，灯具改夹在桌沿。`tools/capture_environment.gd`使用独立Camera3D做特写，避免SpringArm内部更新覆盖镜头；特写与玩家默认镜头分开登记。

验证状态：本项目验证一次，详见`docs/2026-09-29_P1开放资产接入与场景样本验收.md`。不保证未来任意家具/移动障碍都可达；正式人物、美术和玩家体验未通过。下载工具只服务已批准样本，不能据此放宽其他来源的许可审核。

贴图反例：单独tres里的地面贴图已压缩，不代表glTF实际材质的外部jpg也已压缩。本轮模型纹理仍为RGB8且无mipmap，`CompressedTexture2D`类名不是显存压缩证据。遍历实例的Mesh/Surface材质检查`get_image().is_compressed()`与`has_mipmaps()`，修改实际引用jpg的`.import`后重新导入。不要误改仅控制内嵌图片的glTF导入选项。`environment_assets_test.gd`与独立包探针均检查实际资源；前后图形采样保留在P1证据目录，正式批量资产仍须逐类验证。


动作源补记（2026-09-29，验证一次）：官方产品页的120+描述覆盖完整产品，下载到的免费Standard固定2025镜像实际仅46段（含T-pose），必须记录具体版本/子集。保留原作者许可与镜像固定提交、Git blob/SHA256；镜像一致不等于当前官方文件一致。Godot会优化常量轨道，原始通道数不同于导入轨道数。`tools/inspect_animation_source.gd`实测全部片段及根/骨盆轨迹：Roll_RM根位移约4.99m，Walk_Loop根无位移；不能把所有动作直接交给现有速度控制器。骨架命名、静止姿势和轴向与现有MakeHuman不同，重定向尚未验证，不从“可导入”推导“可替换”。

人物材质反例（2026-09-29，验证一次）：高精度MakeHuman眼球的`.mhclo`引用`../materials/brown.mhmat`，其透明声明用于外层；只拷贝纹理并默认不透明时，GLB结构检查0失败但虹膜完全被白蓝外层盖住。复制原材质、相对材质所在目录解析纹理、保留alpha语义后，三人近景恢复虹膜。新增`test_attachment_textures_resolve_from_referenced_material`与`inspect_character_candidates.gd`检查解析目录和眼alpha；旧三GLB重建逐字节一致，限定已有调用兼容。本修复只证明这套资产的遮挡原因，不证明眼睛PBR、发片或所有材质均通过。

选择资源时不能从casualsuit名称推断职业衣装：首轮林岚实际是标志T恤短裤。原始缩略图和完整人体预览分别检查用途与贴合；两轮反例保存在`docs/evidence/2026-09-29-s2-character-pipeline/`。第二轮24图仍发现眉部和嘴角问题，结构检查继续通过，故明确拒绝正式接入；这些未确诊原因见`../unresolved.md`，不将“CC0+能导入”升级为品质认可。

人物真实导入补记（2026-09-29，再次验证纹理机制）：三个GLB导入后的外部PNG默认仍未显存压缩，真实贴图合计469,762,007字节；修改实际PNG `.import`的VRAM压缩后86,682,936字节，mipmap保留。`tools/audit_cast_resources.gd`遍历实例材质的所有Texture2D属性，避免只查albedo遗漏法线/高光纹理；`tests/cast_resources_test.gd`检查真实压缩和每人预算。RenderingServer网格的LOD索引应逐级变少；自动LOD只减少索引，不能声称减少骨骼或全部顶点驻留。前后同位MSAA固定，8张实看图片未发现明显大块损伤，但发片/皮肤美术仍开放，不能将技术成本修复解释为写实质量达成。


2026-09-29 C4d再次验证材质语义：`tree_small_02`的glTF声明混合透明，但叶色JPEG不含透明通道，必须从同一官方资产取得独立alpha再合并。`prepare_city_nature.gd`验证来源后合并RGBA，并设置实际12张纹理的VRAM压缩与mipmap，`city_nature_test.gd`实测36,350,808字节。不能把glTF的alphaMode当作贴图已含正确alpha。Concrete Floor 01的粗骨料颜色贴到连廊立面会产生碎石观感，实际对照后仅保留其法线/粗糙度/AO，另给结构混凝土颜色；地面则降低该颜色混合比例。这个表面用途判断只针对本次场所与素材。枝叶减面另见[拓扑案例](foliage-simplification.md)。

2026-09-30 C4h再次验证独立alpha与实际压缩：Poly Haven公寓模块的glass也共用不含alpha的objects JPEG，须合并同源objects_alpha。三类运行窗墙只需十张贴图，真实压缩mipmap合计30,758,376字节；未使用的trim_02留在制作源，运行包排除原始库。源glTF节点平移用于展示拆开的模块，装配应按实际共享3m开间与底部基准，不能直接复制整库节点位置。

该模块首次空间验证还有两项边界：双窗中间存在实体墙柱，窗洞射线应取真实玻璃三角面内部，而不是假定AABB中心总是开口；室内隔墙顶到外墙同平面会在斜视街景出现竖线闪烁，退入窗后0.3m后同位图消失。`tests/city_architecture_test.gd`分别要求玻璃命中、墙不命中；`tools/render_city_architecture.gd`在真实GPU上检查226个变换的净空，Dummy后端的空变换不能替代。验证范围为这三种模块/三处现有地块；不外推任意资产风格和室内制作均合格。详见`docs/2026-09-30_C4h中心街段建筑制作验收.md`及同位前后证据。


2026-09-30 C4i复用与反例：四项Poly Haven设施中盆栽各部分节点有实际生长位置偏移，卷帘门的多节点则是库中不同变体；二者不能用同一种“全部忽略平移”处理。墙灯应按源z=0壁面安装，不能由最小Y猜支撑面。首次图形实际看到灯悬空，改到门柱后，26个GPU实例的背面射线全部命中实体。射线必须在冻结场景process_mode之前执行；冻结会移除物理参与，曾造成26处全部误报。参考 `tools/render_city_frontages.gd` 与迭代前后图。

同批19张纹理20,971,800字节。检查alpha时 `get_image()` 的共享Image在原位decompress会改变后续压缩审计观察，须先duplicate再读取；`tests/city_frontages_test.gd` 现按源alpha对比并独立检查实际压缩。灯罩源alpha范围约0.89—0.99，本身不是叶片式镂空；不能强行要求所有透明资源都低于0.5。叶片/灯罩源均值误差分别约0.00051/0.00170，验证一次。

自动LOD也有素材边界：周转箱保留原孔洞/UV时从18,320降至10,206三角形后无额外LOD，多个法线合并角均未达到拟定8K目标；实录调整的12K预算与70m批次剔除，不伪造更低面数。只降低索引，不代表顶点驻留同步降低。灯罩斜视灰块在禁用LOD后图片逐字节相同，不能归因于LOD；其正式玻璃材质仍列入 unresolved.md，不以源alpha通过替代美术签收。
