# 渲染装饰与相机碰撞间隙

信号：玩家视线能交谈，人物已到场，但第三人称画面被巨大近处几何挡住；连续帧仍存在。不要先按人物或UI问题处理。

本例机制：公司侧窗装饰突出于墙体碰撞内侧，默认SpringArm的相机近裁面扫掠留出的间隙不足。`CompanyA/Architecture/@Node3D@94/Glass`和`StaticBatch9`均命中从实际相机到见证者上身九点的三角形观察线。物理射线不检测纯渲染装饰，单看碰撞命中会漏掉它。

诊断：先记录实际相机和玩家位置；等待自然物理帧以排除过渡；先AABB筛选再实际三角形验证。不要仅凭包围盒宣布某网格遮挡。原位临时更换0.25米球形扫掠后9条观察线不再命中两网格，实图能看到人物和投影。保留yaw/pitch、原长度及车辆排除列表。

边界：2026-10-09候选实验验证一次，正式产品尚未接入；半径不是通用值。较大形状在桌边会明显缩短镜头，需要实际对话/墙角/车辆复核。低高频试验须设置物理ticks；仅--fixed-fps不改变默认60Hz物理步长。夹具冻结人物不能用于姿态验收，headless不能证明画面或性能。
