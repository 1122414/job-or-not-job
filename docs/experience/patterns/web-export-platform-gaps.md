# Godot网页导出的平台差异

信号：桌面中文正常，网页HUD/Label3D/菜单显示方框；导出成功但网页启动脚本失败；鼠标捕获在后台页面被拒绝。

机制：桌面可回退系统中文字体，网页必须随包提供。自绘HUD直接读取ThemeDB.fallback_font，不一定服从Control主题。指针锁需要真实用户事件且异步完成，后台自动化失败不能直接认定游戏代码有缺陷。并行编辑时导出成功也不能证明所有运行时脚本可解析。

处理：匹配版本模板；指定网页主题字体并在autoload中设置fallback；初始暂停，点击继续触发捕获；只有观察到捕获成功后才将释放视为自动暂停信号。读取实际浏览器日志并观察画面。重复构建排除build目录，避免导入旧产物。

案例与验证：docs/2026-09-22_网页导出验收.md，WEB-08中文修复验证一次；WEB-09重复构建及ZIP检查验证一次。脚本解析瞬时失败在并行编辑后消失，未将其归因于Web引擎。鼠标完整恢复、存档持久化、音频与Safari仍未验收。

边界：模板ZIP CRC用于传输完整性，不等同发布者签名；字体必须保留OFL。不要因为首次网页导出成功宣称完整玩法/性能通过。
