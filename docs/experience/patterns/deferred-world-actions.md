# 延后承诺需要实际世界行为兑现

2026-09-30，C3j，当前街区验证一次。范围限B公司已有交接及其与生活、岗位接替的连接，不推导整城离线模拟已经成立。

## 信号与原因

对话显示“明早发送”或“同事自行处理”，职业阶段和关系已经改变，实际成果却始终未发送。旧版两分支在推进一天并继续1200物理帧后仍为`project_b.sent=false`。`Career`记录选择、`WorkProjects`生成提案之后，没有负责执行未来行为的消费者。增加更多结果文字无法填补这段因果。

## 诊断与处理

- 分开保存玩家选择、绝对安排时间、实际进度、实际发送人和完成时间；不能把到达日期当成实体已经完成工作。
- 只在活人物真实抵达终端、停稳并面向设备时累积核对进度。危险、交谈、阻挡、暂停和缺席分别检查；恢复后继续原进度。
- 普通寻路的0.15m到达容差不能直接承担精确作业定位。本次读档后到达偏差使朝向不满足作业条件；作业末段使用较小容差，同时保持真实碰撞和移动，不直接摆放人物。
- 同事完成不能授予玩家“亲手接手”的事实。岗位接替后回执必须记录新经办人，原人物的死亡和私人关系仍保留。
- 旧存档没有安排日期，标明未确认并通过实际交谈建立新的安排；不能根据读档时钟伪造过去发生过的发送。

## 有用的反例

未答复的私人邀请与已经接受的约定不同。第二轮连续图形路线在作业阶段记录了`tea/offered`被转成`paused`，玩家并没有答应。修复后已确认安排暂缓保留，未接受邀请撤回，作业期间不自动新增邀请；最终源码路线的全部八个记录点均保持空约定。不要把“保留玩家选择”实现成替玩家接受一个选择。

岗位接替检查也须走真实的平静期。死亡后直接调用一次大`delta`仍可能处于目击者反应阶段；等待现场实际恢复后，现有`Staffing`才安排新人。不能为了让交接完成而清除伤害后果。

## 证据与边界

实现：`scripts/work_handover.gd`、`scripts/npc.gd`、`scripts/social_life.gd`、`scripts/save_game.gd`。检查：`tests/work_handover_test.gd`、`tests/work_handover_save_test.gd`、`tools/render_work_handover.gd`。最终源码的连续路线从求职经书屋、住处到次日交付，记录交付瞬间玩家已在办公室外，原协商事实保留。

手掌可达与精确脚位分别验证；点位接触不证明指尖、衣装或完整表演自然。旧版本检查使用构造JSON，不能外推全部玩家旧档。当前全场景驻留，未验证分区卸载、离线世界模拟或30—60分钟独立玩家体验。
