# 手物接触点、真实皮肤与动画更新时序

适用信号：道具中心贴腕、显隐切换手机、数值接触通过但指尖穿出物件。针对当前 MakeHuman 骨架、程序动画及刚体托举，2026-09-29 本项目验证一次，不外推任意骨架或写实握姿。

机制与处理：

1. AnimationPlayer 求值后再修改手臂；用当前 Skeleton3D 骨骼姿态算物件变换，不依赖稍后更新的 BoneAttachment。`player.gd` 的 `sync_held` 与 `npc.gd` 的手机回调接在 `mixer_applied`。反向顺序会被片段覆盖或落后一帧。
2. 以每个体型的腕/掌骨建立手掌框架，接触标记取实际皮肤表面。仅取中心附近一点会漏掉高于该点的掌根；法线投影搜索必须限定局部三维邻域，初版没有深度限制时误选女性身体其他表面。最高点还须排除指骨权重，否则张指后标记仍跟腕、皮肤已移动，实测分离11.15mm。
3. 接触间距和穿透要分开测。`tests/hand_contact_test.gd` 独立计算导入 Skin 的加权顶点变换，检查到接触点的距离；另在五相位检查皮肤顶点进入物件支撑体积的深度。渲染发现拇指穿出底座后，9.70mm→连续帧2.33mm→最终0.326mm；最后一步使用2mm持物余量，未放宽2mm穿透门槛。
4. 手机保留一个场景实体，按同一相位移动和接触；桌面端必须各体型可达。初版旧男体型差6.67—7.14cm，场景位置向面试官靠近12cm后达到接触要求。不可用拉长骨骼掩盖不可达。
5. 释放保留已求值持物变换；原固定角色前方位置会造成跳变。归属、碰撞、残留速度和存读档另行回归。

6. 驾驶方向盘也需要全转向范围可达。C2a（01b4ea4）初版方向盘离座位过远，直行图看似接触，转向时两手出现68.49/27.78mm偏差；补求解时序没有消除不可达。方向盘z从-0.39移到-0.22、y从1.02到1.05后，33个转向角的主角双掌最大点误差0.007866mm，3名通行驾驶者检查通过。复用mixer_applied并在车辆/角色变换同步后求解；不能只测直行。9图含双向转向已查看，但圆环掌面点不代表完整指尖包覆/穿透或自然换手通过。

反例边界：接触点近零误差并不表示指尖包覆自然；掌面距包围盒0只说明点在盒内，可能穿透；托底也不等于杯柄抓握。现有纸张约40cm、纸箱后半段约38—70cm偏差仍开放，见验收与 unresolved，不把通用IK接口当作对应动作已修。

证据：`tests/hand_contact_test.gd`、`tests/interview_performance_test.gd`、`tools/render_hand_contacts.gd`、`docs/2026-09-29_S4手机取放与持物接触验收.md`。图形夹具必须隐藏 NO_FOCUS 根窗口并明确将 SubViewport 设为 UPDATE_ALWAYS；初次缺少后者只得到黑图，不能作为画面通过证据。当前仅离屏查看，不等于用户试玩。

C3b补充窗口边界：在当前Godot4.7.1中仅root.hide不足以证明后台状态，更新流程见[后台窗口状态](background-window-state.md)；不改写上述历史接触测量，但后续取证必须验证最小化/无焦点/鼠标可见。

## 2026-09-30 C3f：静止托书通过后，进出路径仍可能穿透

信号：三体型五个静止相位接触通过，但翻页前后手腕/前臂进入固定页叠；拉大绕行范围后又出现回手过快。分别检查真实蒙皮顶点、掌面点距离、每帧位移和骨骼长度，不能互相替代。

机制和处理：托书点移到后缘仅解决静止穿透；从下方直接接近转页会经过页叠。先绕到后方，再抬手接触真实纸页铰链，结束后沿书缘外返回。人物根节点在mixer求值间仍会转动/移动，兄弟道具需在根物理变换后再次同步；只重算该场景的接触，不能顺便再次调用会累加头部旋转的既有坐读回调。

验证一次：`tests/city_share_performance_test.gd`先测得3.2286mm静止穿透，路径修正后连续检查暴露另一处穿透；首次全套又以55.283mm单帧位移失败。回手0.6秒延至1.2秒，检查覆盖完整190帧，最终最大29.981744mm，静止/每13帧皮肤样本最大0.953842mm，双掌五相位误差0.007629mm，骨骼平移不变。门槛保持35mm位移/2mm皮肤深度，没有修改骨长或放宽断言。

适用边界：现有三种MakeHuman体型、0.36倍刚性图册与固定封面/页叠。未覆盖每帧全部服装、柔性纸面或自然捏纸；页面刚性转动、道具显隐仍有原型感，不能据此宣称正式表演验收。证据见[C3f阶段验收](../../2026-09-30_C3f街区分享现场参与验收.md)。

2026-09-30 C3j复用：站立终端操作先有可达站位，再在mixer_applied后求掌点。中间版135.75mm、31.62mm误差说明仅调用求解器不足；调整站位/躯干与精确到达容差，没有拉长骨骼或放宽门槛。`work_handover_test`最终7,020个稳定作业帧最大16.351950mm，低于20mm；实际包普通相机及标注诊断相机可见双手位于设备上方。该误差以名义键盘点为参照，包含8mm手部摆动，不代表逐指接触、衣装穿透或正式打字表演通过。范围限当前B同事及同体型岗位接替者；见C3j验收。


## 2026-09-30 C3k：接触求解正确，目标方向仍可能不符合动作

实际普通镜头发现用餐手腕伸到面后。第一次五体型掌点和皮肤专项通过，仍不能证明动作正确：勺子接近嘴时保留了碗边的方向，长柄与手掌目标沿身体后方延伸。改为送到嘴边时勺头朝脸、勺柄朝外，手腕始终保留在面部前方；托碗点也放在碗底的实际支撑范围内。`city_meal_contact_test`在五种实际人物上各采样完整241帧，保留2cm掌点、1cm皮肤门槛，并新增嘴边阶段手腕位于面前的语义约束。

摊主又暴露独立空间问题：人物手里有勺并不代表勺子在锅里；仅从人体局部姿势派生会在柜台外搅动。改用锅的真实位置与可达站位组织长柄勺，首次因柄长不足出现177mm掌点误差；按实际臂长调整后，241帧握持小于2cm且勺头均在锅内，没有伸长骨骼或放宽门槛。

两例均在C3k专项与普通镜头中验证一次。证据入口为`city_meal_contact_test`和`tools/render_street_meals.gd`。逐指包覆、完整食物取放、嘴部进食和正式表演仍开放；不能把新增掌点或空间约束推广成所有动作的视觉验收。


## 2026-10-01 R30：命中距离不能独立于动作接触，掌点通过也不保证握拳

信号：真实攻击输入时已经扣血，旧动画掌点最远只向前0.357475m，而逻辑允许2m徒手/2.7m键盘。给右掌设0.70m目标并不表示导入臂长实际可达；不能拉长骨骼去满足旧隔空站距。先测实际可达路径，再用拳代理或手持物原子形状覆盖有效段；`intersect_shape`不扫motion，须显式采样。当前实现首次有效帧只查当前端点，避免把起手轨迹算进攻击。一次碰到实体即结束本次结果，中断清除临时动作。

第一次逻辑全部通过但图形仍张掌；增加四指curl后拇指仍张开。实际近景暴露 wrist方向与拇指对掌需独立处理，修正后再次逐物理帧运行和近景查看。四指点位断言只证明折回范围，不证明拇指、完整皮肤无穿插或正式动作质量。原胶囊互相重叠的双目标夹具会使can_see拒绝，并非多目标算法失败；保证有效站位再验证。一旦改为真实时间，书屋等后果测试应在命中时取冻结基线，不能要求起手期间也停止世界。救助/反击应在造伤夹具结束后恢复真实行为，仍保留全流程后果断言。

本机现有男性角色验证一次：`tests/attack_window_test.gd`首击0.116667s，0.75m近身通过、1.5/2m远处和薄墙失败接触、骨平移未变；`tools/render_player_strike.gd`源码/实际包均有关闭四指和拇指的拳手近景。仅为玩家当前前向动作；不同骨架、正式服装、逐面皮肤碰撞、全部低帧率与NPC反击不据此通过。证据见[阶段验收](../../2026-10-01_玩家挥击动作与命中同步验收.md)。
