# 视觉参考不能只拆成 HUD

2026-09-30宏观复核再次应用此边界：用户要求停止局部细节讨论、先看与GTA的宏观距离。C4j工程已有95项Godot和32项Python通过，但当前街道与面试画面、主线验收仍未支持完整城区和正式视听完成。报告须分开已有功能、整体玩家体验与整城生产能力，不把测试数量或部件交付数折算成品质百分比。记录与两张取证图见`docs/2026-09-30_GTA目标宏观差距复核.md`及`docs/evidence/2026-09-30-c4j-bus/`。此结论为当前记录和图像复核，不是新一轮完整玩家试玩。

适用信号：用户给第三人称游戏截图并说“UI 像这个”，随后明确指出“不要方块人”。

本次事实：仅实现圆形地图、生命条和星级后，用户再次指出整体人物/场景不符合方向。错误假设是把截图参考缩窄为二维控件，忽略占据画面主体的人体比例、服装、镜头和办公空间。

处理：先按当前用户明确纠正覆盖角色、动画、镜头、光照和空间，保持既有玩法范围；在实机看整幅画面，不能用单独 HUD 检查替代。`scripts/human_visual.gd`、`scripts/office_dress.gd`、`scripts/player.gd` 是本次落实点；资产来源单列 `docs/assets.md`。构图方向已实际观察一次，但美术满意度尚未得到用户最终确认，不能据此推广为任何截图均要求完整复刻。

骨骼回归的附带发现：AnimationPlayer 有交叉淡入时，切换后第一次 `advance()` 得到的腿骨可能仍是原姿势。`tests/visual_test.gd` 等待连续 15 个实际处理帧再观察非单位旋转，能验证运动；首帧非零不是合理验收条件。本项目验证一次，仍须保留实际画面检查来发现脚滑或穿插。

2026-09-22 反例：18 项回归通过后，实际坐工位仍出现头部低至桌面，一次空手攻击令办公桌坍低。`docs/2026-09-22_实际试玩问题记录.md` 记录实际动作和观察范围。功能存在、归属唯一、路径可达，只证明对应逻辑；坐姿比例、打击力度、人物辨识和可信面试场景需要各自的体验验收。用户明确纠正 WASD 移动正常，不应将自动控制工具短按限制登记为游戏缺陷。

2026-09-22 第三轮补充：未入职预览 J 页面只有泛化去向，员工在入口视角被家具遮挡。减少常驻文字必须同时提供目标与地点可读性；人物模型存在也不等于玩家能找到人物。修复优先级需包括基础画面和开局理解，不能全部推迟到 Blender 阶段。MVP 文档明确禁止用独立工作小游戏或重复劳动替代场景处境，后续建议须保留这一边界。

2026-09-22 连续渲染路线补充：截图发现演示已预览却仍以HR旧欢迎为主目标；分段测试未模拟“跳过欢迎继续工作”。R22改为未读来访列表、可选导航，当前阶段来访独立排程，GUI J→4→3已验证。B欢迎确认后继续同一对象的帮助/拒绝/协商，避免再次E被附近面试工位抢走。tests/full_route_test.gd连续步行路线、office_life_test阶段跨越与GUI覆盖该机制，27项回归通过一次。画面/动作自然度仍不能从这些状态断言推导。

2026-09-22 v0.5反例：工作状态全部正确，渲染路线仍发现完整预览文字溢出实体白板。给世界内Label3D限制宽度、按成果字段换行、独立复拍，不能依靠状态断言发现排版缺陷。后台图形夹具等待frame_post_draw可能停住而世界继续推进；暂停世界、等待Control处理数帧后force_draw用于确定性截图。只force_draw未等UI处理曾得到旧画面。该捕获方法验证一次，不替代连续动态路线；最终证据见求职荒诞体验验收阶段7。

2026-09-23 面试演出反例：B 公司字幕写“推箱、发语音”，模型虽有通用手势，桌上箱/电话未移动。把叙事动作写进文字并不能完成玩家要求的“真实演出”。改为句段绑定骨骼动作与世界道具位置/显隐，并用同一镜头的多帧截图及中断后恢复断言分别验证；见 `tests/interview_performance_test.gd`、`docs/2026-09-23_面试演出与沉浸体验复查.md`。基础同步验证一次，物件接触、表情和动作自然度仍未验证通过。初次 A 图形夹具误用 B 落座动作，玩家站立遮挡属于夹具错误；复查取景时必须先断言实际坐下，再判定相机问题。

2026-09-23 第二轮定位：`scripts/human_visual.gd` 中三种专用面试动作的骨骼曲线缩进在 `read/write/message/pause` 分支内；动画名称存在、物件移动且状态测试全绿，却没有专用肢体动作。诊断时同时检查曲线是否真正生成、骨骼世界位移及正常渲染中的手物距离；不能只断言 `animation.has_animation()`。修正后 `tests/interview_performance_test.gd` 的腕骨位移与关键帧检查通过一次，照片仍暴露精细接触误差。`tests/interview_call_test.gd` 另验证叫号 NPC 真正走到门口、受位移打断后重来及旧存档回退。该方法针对本项目程序骨骼与道具同步，不足以证明写实演出质量。

2026-09-29 品质门槛再验证：用户明确参照升级为GTA VI展示水准、预算后定。当前 `tests/interview_performance_test.gd` 以手腕距箱中心<0.60m证明接近，不能证明手掌/手指实际托住物件；`panels_test.gd`通过时，默认1280×800帮助页末行基线仍在底板下32px（R29）。本轮4项定向检查全部通过，但17张当前画面仍暴露表演、材质、构图与UI缺口。处理时为每条断言注明它证明的属性，另设接触区间/真实表面距离、文字边界和正常游玩视听评审；不能仅增加状态断言继续宣布品质完成。边界验证再次成立，新的品质修复未实施。证据与复现见 `docs/evidence/2026-09-29-audit/README.md`，问题表见 `docs/2026-09-29_GTA6品质差距全面审查.md`。官网目录可读而大图CDN失败时只记录来源，不能据此虚构逐帧参照比较。


2026-09-29动作源适配再次验证混合时序：新增`authored_motion_test.gd`最初用一次`advance(0.25)`评估0.2秒混合，2691条局部骨骼差异实际来自首轮混合权重；15次1/60步进后同一阈值通过。该机制现已重复验证，手动step检查必须模拟连续帧。新增动作驱动更多骨骼时，所有出口片段须拥有对应重置轨道，检查交谈到受击/坐姿/持物等19出口与独立播放姿态一致；当前三套人物共用骨架，不能外推不同体型。

同轮制作工具反例：删除AnimationPlayer仍指定的临时对照片段会使后续stop/seek遇到悬空缓存，本机Godot4.7.1图形先崩溃，先stop再删除仍报Animation not found。截图工具改为每个对照独立命名并保留到角色释放后，20图无错误；不要通过运行时删除当前资源来做前后对照。仅在本机工具验证一次，不声称普遍引擎根因已证明。


2026-09-29 C3d重复验证观察时序：居民seated标记刚变真时，朝向/根高度及动画混合尚在过渡，立即冻结会误判最终坐姿。取证改为实际靠近阶段对准长凳、落座后连续运行45帧再截图；最终三处场所、阅读、邻座、玩家加入/起身共8图已看。此等待只用于本项目当前过渡，不是可推广的固定延迟，也不代表正式坐下/起身动画已制作。反例与最终图见`docs/evidence/2026-09-29-c3d-commons/`。
