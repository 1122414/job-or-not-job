## 1. 结论与范围

用户补充后，下一步优先验证A公司“明确有转正HC的承诺→长时间实习投入→成果合格→最终不能转正→玩家回应”的完整体验。先选有时间跨度的关键场景串成短章节，不以扩城或生活支线作为核心验收。游玩时长和实习月数未由用户指定，不把原10—15分钟小样或四周设定当作新确认值。

当前已确认方向：荒诞职场，突出提前说好有转正HC、实习很长时间后仍不能转正。自主生活作为离场后续与情绪间隔，不能替代这一核心。10月8日已确认的导师拒绝、承诺落空、最终仍无录用继续有效；自由选择公司和面试不等于每家公司都必须录用。叙事可以规定宏观结局，但需要验证过程中的行动是否仍有局部影响。

检查范围：README、原始评审稿、10月8日秋招计划及验收、10月9日反馈/NPC/内嵌对话验收、相关经验；职业/秋招/任务引导/工作交付/道具/自由聊天的部分源码；三张已有构建截图。本轮没有从头真人试玩、听音评审、性能基准或云端模型实测，不代表全项目审计。旧稿中的单公司范围和转正路线不覆盖后来的已确认变化。

本轮使用五项方法：core-loop-extractor提取动机循环；prototyping-companion组织试验分支；game-feel拆分动作反馈；game-ui-ux检查信息与现场的关系；playtest拟定观察问题。试玩方案仍是草案，人员、样本与具体安排尚未确认。

## 3. 核心循环

现有职业链：争取实习 → 秋招 → 接受承诺 → 实际工作 → 未转正 → 后段投递 → 无录用。这是有限叙事链，本身不构成可以反复进入的核心循环。

建议验证的即时循环：看见具体矛盾 → 选择说、做、动手或离开 → 看到人物与场景变化 → 获得新的信息、关系或行动机会 → 决定下一步。

建议验证的实习阶段循环：接到新的要求 → 核对范围并选择处理方式 → 做出可见成果 → 得到肯定和下一次转正承诺 → 带着既有成果进入下一阶段。每次推进增加新矛盾或证据，避免重复劳动填时长。生活循环作为辅助：自己安排去处 → 遇到一个处境 → 介入或无视 → 世界记住做过的事 → 下一次相遇出现差异。奖励可以是被理解、腾出自己的时间、留下成果或打开一种互动，不需要把全部行为折算成钱和经验条。

最小改动方向：只选一个现有处境，将“真实行动—现场反馈—后续变化”接通。不统一重构所有事件，不先添加通用事件编辑器。

## 5. 优先章节：《说好的名额呢》

2026-10-09用户明确补充：“荒诞职场+职场实习了很长时间却不能转正（提前说好了有转正hc）”。据此将A公司章节升为首选；上一版《今天能按时走吗》保留为支线候选，不再作为首个开发阶段。

| 阶段 | 玩家实际参与的事（候选） | 应留下的证据或变化 |
| --- | --- | --- |
| 接受承诺 | 面试时问清HC、实习期限和考核条件，核对原接收通知 | 清楚写明有转正HC和达标条件，不能开局就偷换成只“有机会” |
| 第一次投入 | 沿用正式资料/草稿、离线/权限选择，完成实际演示交付 | 主管确认通过，成果有本人职责；工位和同事反应承认玩家已在工作 |
| 更长时间的投入 | 用第二份已有成果、换组和少量关键场景表现职责增加；阶段间由玩家主动推进时间 | 工牌/工资记录、日期、项目版本、人物称呼或公司安排的变化，至少两种相互支持；单一弹窗“几个月过去”不足以验收 |
| 期待再次建立 | 在后续关键节点追问转正时间，收到更具体的答复或可核对记录 | 记录当时确实作出的承诺；如采用延期，每次需有新处境，不能用同一话术无限拖延 |
| 承诺落空 | 玩家带原通知和通过记录进入评审；公司承认成果合格，却不能兑现名额 | 原承诺与现在口径可并列核对；不将落空解释为玩家没选对答案或考核不合格 |
| 玩家回应 | 可追问、要求书面说明、请见证者到场、离开或动手打断 | 有不同的现场反应与关系记忆；本章仍不转正，不把攻击变成拿HC的隐藏正确解 |

“实习很长时间”优先用少数关键工作日与阶段变化来表达，让玩家亲自做决定、留下成果。具体几个月、是否延长现有四周和增加几次评审尚未确定；若改变日历，必须同时核对毕业/秋招窗口、工资、约定和旧档，不能只改28这个数字。

荒诞来源应紧贴规则矛盾：一个实习生被要求承担熟练员工工作，考核时却仍被说缺经验；主管明确确认完成，HR又将“有名额”改称“当时的用人需求”。这些是候选虚构场面，不是已实现剧情或现实企业事实。对白、动作和可互动道具共同呈现，避免只增加长台词。

## 7. 验收草案与基线复核

不先告诉玩家“要打人”或“要帮阿乐”。先让其自然操作，再单独提供替代处理任务。记录首次自主行动、首次停滞、主动询问、想结束的时点，以及原话。以下期望是本项目候选验收条件，不是行业基准；必要时按首轮观察校准。

## 8. 从《渔力全开》可以迁移的经验

开发者在发售前访谈中提到持续展示新功能的视频，并形成社区；这支持“开发过程中验证可理解的场面”，不证明某个玩法组合必火。来源：[Sweden Game Arena，2026-03-02](https://swedengamearena.com/en/news/dazed-games-secures-project-investment-and-sets-sights-2026-launch/)。

本项目可迁移的是熟悉处境、可见的意外、清楚的因果、再次尝试的空间。单人版应先靠NPC和场景反馈完成这一点，不能把他作的多人传播效应直接套用。可先内部展示一段真实的“提出今晚交付→发现原消息→陪同核对→一起离开”作为后续支线；当前优先展示“明确有HC→成果通过→拿原通知对质→公司改口”的真实片段，让未玩过的人复述前因后果；本轮不发布视频。
