# Grill: 今天不上班 MVP 范围与核心玩法
Date: 2026-09-21
Status: 本轮结论已整理；方案评审中，未开始实现。

## Intent
“让玩家爽是第一位的”。自由破坏是基础，仅破坏不够深；玩家可以认真做事，也可以不忍、离开，通过不同选择改变机会和人物关系。体验要直接，不做细腻生活模拟。

## Constraints
Godot、第三人称、从首次可操作起允许动手和中断流程。持续世界，不强制清档。必须是可自由步行的连续小街区，两家公司都能随时前往，不以第一家公司剧情进度解锁第二家。当前只敲定 MVP 文档，不写代码。

## Key decisions
- 执行约定：先交付按优先级与 Phase 划分的本地实施计划，当前不开发。未来开始实现后，由助手自主决定各阶段的合理子阶段颗粒度；每个可独立验收的子阶段检查通过后进行中文 Git 提交，完整 Phase 汇总验收，不把无文件变化的验收强行做成空提交。
- 决定：背包不设负重与格子整理，小件自由收纳；键盘、杯子可携带，桌椅、打印机等大件留在现场推、掀、砸。原因：方便切换道具、保持爽感，不以背包管理增加负担。
- 决定：随时可掀桌、打断当前处境；玩家被打死后可以复活，初版不因死亡掉落任何装备。加入背包系统，支持存放与取用物品。原因：保持自由行动和爽感，不用死亡后的装备追回劳动惩罚玩家。复活采用短暂倒地后在附近安全点恢复操作，并给短暂保护，不强制回家或长距离跑图；装备、关系及职业后果保留，具体时长留待试玩调整；本次没有要求 NPC 永久死亡。
- 决定：第一份工作采用零散协作的演示交付，资料、权限、确认人分散，要求边做边发现；允许取消或绕过不必要的要求。原因：玩家爽是核心，不能让玩家现实上班后在游戏里再上班；新增要求不等于新增必做清单。
- 决定：第一家流程压人，第二家人情压人。原因：换公司要改变处境；不做两套相同流程，不做明显的好坏二选一。
- 决定：第一家保留三轮短面试、无正式名额后的实习邀请。原因：面试本身是职场荒诞来源，不能以缩范围为由删去。
- 决定：第一家完整路径为实习产出、考核通过、无 HC、推荐换组继续实习、第二次产出、转正答辩、实际转正。原因：荒诞来自通过后仍被要求重复证明，不能改写成普通刁难后直接转正。
- 决定：换组后用更短且要求不同的事件产生第二次成果，不机械重做第一项工作。第二家保留面试、入职和人情冲突，不复制整条转正线。
- 决定：工作通过场景内对话、找资料、交付、突发状况实现，不做独立小游戏。原因：保持自由行动和场景交互的一致性。
- 决定：普通冲突可以真正失去机会；明确警告后反复主动升级才可能永久决裂。原因：后果有分量，但不因单次混乱直接封死职业线。公司决裂不传播至另一家公司，个人关系单独判断。
- 决定：靠近、接触人物时显示情绪文字、好感度条、关系标签；不显示体力条、情绪强度。好感依据立场变化，关系标签可并存；高好感不覆盖人物底线。
- 决定：仅两三位重要同事有下班短互动，离职后仍可见面；只在少数重要事件后主动联系，不做打卡维护。
- 决定：加入余额、发薪日和到账记录，在职期间不因闲逛、不完成任务而直接停薪；离职前应得工资保留至发薪日到账。不做消费、商店、绩效、考勤、扣款及单独赚钱任务。工资周期与金额未定。
- 决定：裁员剧情暂不做；玩家行为导致的解雇、主动离职与公司决裂保留，两者不是同一机制。

## Surfaced assumptions
原稿单家公司是建议，用户已明确替换为两家；不能把文档建议当用户硬要求。不能把“核心优先”解释为删除面试与实习转正；它们是用户明确保留的核心体验。不能把对功能方向的认可解释为立即开始编码。零散工作不等于必须跑完的碎任务；设计要允许减掉工作，而不是不断加码让玩家劳动。

## Open questions
第一份演示交付的具体交互与捷径、换组产出及第二家公司事件的具体内容；发薪周期、金额及离职应得工资的最简计量方式；复活等待与保护的具体时长、NPC 总数、正式美术、发行平台、测试设备和排期尚未敲定。

## Out of scope
本轮只做方案。产品 MVP 不做消费、复杂经济、生活经营、独立工作小游戏、裁员剧情、跨公司声誉传播与复杂社交养成。
